## Observations (not defects)
1. AC-19 says "no audit row is written in any case", while the body with an ignored `"defaultLanguage":"ar"` is otherwise a valid no-op `PUT`, which AC-21 and AC-40 audit (200 outcomes, including the no-op). The implementation returns 200 and writes one audit row, and the code review accepted this as a stage 3 deviation. All 400 cases wrote no row. The AC-19 wording should say "no audit row for the 400 cases" at the next story edit.
2. When the anonymous `GET /languages` fails, the web app makes the call twice before sign-in (one retry); with success it is exactly one call (AC-32). Harmless.
3. The device config notifier (AC-17) is a no-op in M2 and cannot be observed on the real host; it is verified by the recording-double test.
4. Review follow-ups S1 to S4 and N1 to N6 are unchanged and not defects. The `/languages` endpoint treats an invalid token as anonymous (200), as accepted in review.
5. STORY-004 AC-3 and AC-17 were run on the ar-enabled stack (section 10 of the story): accepted as the re-based check.
6. Not tested: Android and displays (no work in this story). Manual Sunmi device checks: none.
7. QA tooling: one early curl run with cached tokens returned 401 "signature key was not found" on `/company-languages`; fresh logins (three in a row) returned 200 every time and the run was repeated cleanly. Not reproduced and the cause is unknown; if it ever recurs, file it as a bug against stage 3.
